# V9.0.3 客户需求分析 Agent · 第一阶段

入口：`/analysis/needs`，从「智能业务分析」进入。沿用恢复后的独立知识库连接，不修改数据库、索引、密钥或原有12个恢复文件。

## 实际工作流

StateGraph：输入校验 → 客户信息结构化 → 明确需求提取 → 待客户确认的沟通优先级 → 信息缺口和追问 → 检索计划 → knowledge_search → 当前原文和版本检查 → 逐资料字段提取 → 责任字面关联和未知项 → 报告 → Word/PDF。

没有明确需求时跳过检索，没有证据时跳过产品提取。字段提取复用 V9.0.2 原文核验，最多3个需求、3份候选和5个片段，总计12000字；并非全部条款审查。每个节点及工具开始、完成、失败、取消事件均由实际执行生成。格式校验最多重试一次，图步数和请求时间受限。取消后不启动后续工具。

## 事实与隐私边界

只从客户明确输入提取需求。优先级按原话顺序整理为待确认沟通顺序，不由年龄、性别、收入推断风险或保险适合性。缺失资料不代表责任不存在；所有预算匹配、投保条件和完整费率仍须核实。

Mock 使用规则整理需求并调用真实本地检索，不伪造产品字段或模型分析。DeepSeek 沿用现有配置，只有用户选择真实引擎且确认外发和费用才调用。自动化测试禁止真实网络。默认不保存客户输入到浏览器或知识库；报告沿用受控本地临时目录、60分钟下载凭证和来源重核机制。不要填写真实身份或未经授权的健康隐私；本地单用户演示，不直接公开部署。

## 报告修改

修改客户信息后重新分析。也可以通过 `/api/needs/revise` 编辑沟通备注：必须持有有效报告下载凭证，备注独立标注「未核验」，没有来源编号，不覆盖任何产品事实。更新报告会产生新下载凭证；旧文件不被覆盖。每次导出重新核对文档有效性、版本和证据内容。

## 第二阶段：真实 AI 与证据质量

沿用 DeepSeek 官方端点、现有服务端密钥及模型配置。需求整理和 AI 判断使用流式 JSON object 响应，每次调用限45秒，格式或输入依据不符最多修复一次。产品提取复用对比引擎，按每份资料分别调用并核验；默认最多3份，因此单轮通常为需求整理1次、AI判断1次、逐产品最多3次，格式重试会增加调用。页面必须确认资料外发及费用。Mock 保持规则模式，不冒充 AI 判断。

新增 ai_analysis 节点，只将授权客户输入用于判断；摘要、潜在缺口、沟通优先级和追问全部属于待确认的 AI 分析。每条缺口和优先级须包含实际输入字段的连续原话依据。原文证据继续由产品摘录核验，四种状态为已找到依据、部分找到待人工核实、资料未提供、无法确认。相似度只用于召回。产品调用失败保留中文原因；全部失败不生成成功报告。

报告沿用八章节格式，将客户填写、AI判断、资料原文、未知字段和建议分层呈现。页面显示引擎、完成时间、来源数量与字段状态。超时、安全失败、取消和版本变化均结束后续执行；不默认持久化客户信息，不启用远程 tracing。

## 客户需求自动检索修复

原入口只把类别模板交给既有向量检索，可能丢失原需求中的产品名称；宽泛责任词可能低于既有校准阈值。现在保留完整的明确需求，以受限查询计划复用向量检索，并在客户需求入口增加实际文档名、责任词和字段词的只读关键词候选。没有降低共享向量阈值、没有重建索引，也没有改变其他聊天或对比模块的检索行为。

关键词仅产生候选，不能证明责任或客户适用性。关键词候选不伪造余弦分数；候选按两路排名融合、去重，再限制到最多3份文档和5个片段。所有候选均重新检查当前版本和有效状态；未知的显式文档名称不会借用其他产品补齐。未识别的其他需求不自动扩成笼统的保险字段查询。索引损坏、模型异常会失败，不转成“没有资料”。

每个真实检索步骤的 SSE 事件包含查询词、本机知识库安全标识、有效文档数、命中文档名和版本、片段数、检索方式及原因。失败和取消保留当次查询与异常说明；完成结果关联本轮诊断，不写入客户历史缓存或公开日志。界面在执行记录中展开查看，引用卡片可核对实际片段和页码。

## 第三阶段：产品证据与对比

在原有节点内部扩展证据层，不更换客户表单、节点路径或共享的产品对比引擎。客户需求使用独立的12字段提取协议，在原10字段上增加保险公司和其他重要限制。旧测试适配器可省略新增字段，但缺失项只显示未找到，不能由常识补齐。Mock默认不伪造产品提取；真实引擎复用原DeepSeek配置、受限JSON输出和一次格式修复。

产品正式名称来自明确名称标签或可辨识的保单/产品说明书标题；计划书名称和文件名仅定位资料。公司名称需要明确承保标签或“我们”定义等原文依据，不从品牌前缀猜测。每个字段保存已找到、未找到、无法确认三态和真实文档、版本、页码、切片及逐字摘录。等待期不取犹豫期，客户案例年龄不证明投保条件。同一资料出现多个身份时，不将其责任字段归给单一产品。

同一产品的片段去重；跨文档仅在正式名称和公司均有依据且一致时归并。冲突不选择一方，保留不同原文值和出处并清空确定值。证据超过容量时明确失败，不能静默丢弃冲突。不同产品独立显示；至少两项正式身份可确认时展示产品对比，否则显示候选资料核验，不作产品排名。

网页增加字段原文与冲突详情、产品归并清单和12行对比。报告保留原八章契约，将检索结果、产品清单、字段对比、原文及页码、缺口与沟通建议纳入原章节；Word/PDF共用经校验数据。没有足够原文的字段继续标待核实。下载时仍校验当前有效版本。

测试命令在现有专项列表中增加 `tests/needs-product-evidence.test.ts`。新增测试覆盖身份、公司、多片段去重、多产品隔离、跨文档归并、冲突、缺失项、错误来源、版本、等待期/案例混淆、对比及Word/PDF。

第三阶段真实资料验收采用正式库只读副本，5个实际片段、两份产品文档，通过原文规则核验名称、公司及版本，生成12行对比和5条引用；DOCX可解析，PDF中文可提取。此项没有调用付费模型，也不以注入的原文规则提取器冒充真实LLM。新版12字段DeepSeek调用及完整真实模型分析仍待网页验收。个别资料可读文本中缺少正式名称时保持未找到/待核实，不从文件名补造；不为此修改生产索引或文档。
